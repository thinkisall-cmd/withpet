# DogWalk 앱 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 동네 강아지 산책러들이 실시간으로 서로의 위치를 지도에서 확인하고, 강아지 정보를 공유하는 Capacitor 앱 구축

**Architecture:** Next.js App Router를 Capacitor로 감싸 Android 앱으로 배포. Supabase Realtime으로 `live_locations` 테이블 변경을 구독해 마커를 실시간 업데이트. 위치 수집은 Capacitor background-geolocation(앱 환경) / navigator.geolocation(웹 개발 환경) 이중 경로.

**Tech Stack:** Next.js 14 (App Router), TypeScript, Tailwind CSS, Supabase (Auth/DB/Realtime/Storage), 네이버 지도 API v3, Capacitor v6, @capacitor-community/background-geolocation, Vitest

**Spec:** `docs/superpowers/specs/2026-11-05-dogwalk-design.md`

## Global Constraints

- 반경 필터: 클라이언트에서 1km 초과 마커 숨김 (`haversine` 거리)
- 위치 업데이트 스킵: 마지막 전송 좌표에서 5m 미만이면 클라이언트에서 전송하지 않음
- 성격값(temperament): `'gentle' | 'normal' | 'caution'` — DB CHECK 제약과 일치
- 성격 뱃지 색상: gentle=초록(`#22c55e`), normal=노랑(`#eab308`), caution=빨강(`#ef4444`)
- 산책 종료 시 `live_locations` 행 즉시 삭제 (집 근처 좌표 노출 방지)
- 공유 URL 패턴: `/walk/share/[token]` — 로그인 없이 읽기 전용
- Android 우선, iOS 미지원 (이번 버전)
- 모든 API route는 `SUPABASE_SERVICE_ROLE_KEY`를 사용하지 않고 사용자 세션 JWT로 동작 (RLS 활용)

## Review Focus

- **산책 종료 없이 앱 종료**: `live_locations` 행이 남아 유령 마커가 생김 → Task 6 `POST /api/walk/end` 호출 보장, Capacitor `appStateChange` 리스너에서 종료 처리
- **공유 링크 월권 접근**: 다른 사람의 `walk_session` ID로 share_token 생성/취소 시도 → Task 8 share API에서 `user_id = auth.uid()` 조건 검증 테스트
- **동시 산책 세션 중복**: 이미 산책 중인데 다시 시작 요청 → Task 6 start API에서 `ended_at IS NULL` 세션 존재 시 400 반환 테스트
- **5m 중복 제거 경계값**: 정확히 5m 이동 시 전송 여부 → Task 6 `shouldSendLocation(prev, curr)` 단위 테스트에서 경계값 확인
- **빈 강아지 목록으로 산책 시작**: 강아지 미등록 사용자가 산책 시작 버튼 누를 때 → Task 6 start API에서 `dog_ids` 빈 배열이면 400 반환 테스트

- [ ] **Step 1: 마이그레이션 파일 작성**

아래 순서로 작성:
1. `users` 테이블 (id = auth.uid() 연동을 위한 PK 타입 uuid)
2. `dogs` 테이블 + temperament CHECK
3. `walk_sessions` 테이블
4. `walk_session_dogs` 테이블
5. `live_locations` 테이블
6. 각 테이블 RLS 활성화 + 정책:

```sql
-- users: 모두 읽기, 본인만 쓰기
CREATE POLICY "users_select" ON users FOR SELECT USING (true);
CREATE POLICY "users_insert" ON users FOR INSERT WITH CHECK (auth.uid() = id);
CREATE POLICY "users_update" ON users FOR UPDATE USING (auth.uid() = id);

-- dogs: 모두 읽기, 본인만 쓰기
CREATE POLICY "dogs_select" ON dogs FOR SELECT USING (true);
CREATE POLICY "dogs_write" ON dogs FOR ALL USING (auth.uid() = user_id);

-- walk_sessions: 본인만 읽기/쓰기 (공유는 share API로)
CREATE POLICY "sessions_own" ON walk_sessions FOR ALL USING (auth.uid() = user_id);

-- walk_session_dogs: 본인 세션만
CREATE POLICY "wsd_own" ON walk_session_dogs FOR ALL
  USING (EXISTS (SELECT 1 FROM walk_sessions ws WHERE ws.id = walk_session_id AND ws.user_id = auth.uid()));

-- live_locations: 모두 읽기, 본인만 쓰기
CREATE POLICY "live_select" ON live_locations FOR SELECT USING (true);
CREATE POLICY "live_write" ON live_locations FOR ALL USING (auth.uid() = user_id);
```

7. `live_locations` Realtime 활성화:
```sql
ALTER PUBLICATION supabase_realtime ADD TABLE live_locations;
```
